The macro and the web panel exchange parameters as a comma string:
`mn,z,alfN,beta,x,bw,bore,type,keyway` — e.g. `2,20,20,0,0,20,12,EXT,1`.

### Derived quantities

```
mt = mn/cosβ                 αt = atan(tanαn/cosβ)
d  = mt·z                    db = d·cosαt
external:  da = d + 2(ha*+x)mn     df = d − 2(ha*+c*−x)mn    sT = mt·π/2 + 2x·mn·tanαt
internal:  da = d − 2(ha*−x)mn     df = d + 2(ha*+c*+x)mn    sT = mt·π/2 − 2x·mn·tanαt

k    = round(z'·αn/180 + 0.5),  z' = z·invαt/invαn
W    = mn·cosαn·[π(k−0.5) + z·invαt] + 2x·mn·sinαn
zmin = 2(ha*−x)/sin²αt       xmin = ha* − z·sin²αt/2       zv = z/cos³β
```

Pin measurement, with `dp = 1.68·mn` by default:

```
inv αM = inv αt ± dp/(mn·z·cosαt) ∓ π/(2z) + 2x·tanαn/z      (external + −, internal − +)
RM     = rb / cos αM
M      = (z even ? 2·RM : 2·RM·cos(π/2z)) ± dp                (external +, internal −)
```

## 2. Tooth profile generation

The half profile is built in a **tooth-centred frame** — the tooth centre lies at 0°, profile
points carry negative angles, and the other half is the mirror `y → −y`.

### 2.1 Involute portion (analytic, exact)

```
θ(ρ) = sT/(2r) + inv(αt) − inv(αy),    αy = acos(rb/ρ),    inv(a) = tan a − a
```

### 2.2 Root fillet (rack-cutter envelope)

A standard rack cutter with a rounded tip rolls without slipping on the pitch line. The fillet is
the **envelope** of the cutter tip round.

```
a0 = π·mt/4 − x·mn·tanαt                          cutter half thickness at the pitch line
h  = (ha* + c* − x)·mn                            cutter tip above the pitch line ( = r − rf )
rc = ρ*·mn,  capped at (a0 − h·tanαt)·cosαt/(1−sinαt)     the tip must keep a flat land
Cy = h − rc
Cx = a0 − Cy·tanαt − rc/cosαt                     fillet centre, cutter frame
```

Translating the cutter by `u` turns the gear by `φ = u/r`. By the **fundamental law of gearing**
the common normal at the contact passes through the pitch point, which sits at the origin of the
world frame. So the contact point on the tip round is the centre pushed outward by `rc` along the
line from the pitch point:

```
Cw = (Cx + u, Cy)
P  = Cw + rc · Cw/|Cw|
```

Then transform into the gear frame (rotate by `−φ` about the gear centre at `(0, r)`) and finally
into the tooth-centred frame (rotate by `ζ = π/2 − π/z`).

Sweep range `u ∈ [−Cx,  Cy/tanαt − Cx]`:

- at `u = −Cx` the fillet touches the cutter tip land — the point lands **on the root circle**
- at the upper limit the fillet touches the cutter flank — the point lands **exactly on the
  involute**, so the two curves meet tangentially with no fitting required

The **bottom land** half-angle is `Cx/r`; it is generated by the flat of the cutter tip and is a
true circular arc. Note that `Cx` is independent of the profile shift `x` — the two `x` terms
cancel.

### 2.3 Undercut

While sweeping, if a trochoid point at radius `ρ > rb` satisfies `θ_trochoid < θ_involute(ρ)`,
the cutter has removed involute flank at that radius. The profile is truncated there and the
involute restarts from that radius.

This is not a special case bolted on — it is what the envelope does. `z = 10 / 12 / 14` report
undercut; `z = 17 / 20 / 40` do not, matching `zmin = 2ha*/sin²αt = 17.097`.

The sweep density (≥ 60 steps) is **decoupled** from the output density (`Npts`) so the crossing
is never missed at coarse output settings.

### 2.4 Degenerate-point removal

Consecutive points closer than **1e-5 mm** must be removed. The manually added root start point
and the `u = −Cx` trochoid point are mathematically identical; leaving both makes SOLIDWORKS
create a degenerate spline, which it then **silently discards** — opening a gap in the profile so
the extrude fails with no diagnostic.

### 2.5 Pointed teeth

When `θ(ra) ≤ 0` the tooth has become pointed. Solve `inv(αy) = sT/(2r) + inv(αt)` for the
pointed radius, clamp `da` to it, and warn.

### 2.6 Internal ring gears

The involute formulas are the same (with the internal `sT`, `da`, `df`). The root fillet is a
tangent-arc approximation: the centre lies on the involute offset normally by `rc` **and** at
`|C| = rf − rc`; a bisection finds the tangency. A true internal fillet is generated by a shaper
cutter and depends on the cutter's tooth count.

## 3. SOLIDWORKS modelling

### 3.1 Architecture

```
1. sketch tip circle on the front plane   → FeatureExtrusion3   (blank)
   internal only: sketch circle at ra     → FeatureCut4         (centre hole)
2. sketch one tooth space (6 segments)    → FeatureCut4  ThroughAll
3. top plane ∩ right plane                → InsertAxis2         (the Z axis)
4. FeatureCircularPattern5 on the cut, ×z
5. bore + keyway                          → FeatureCut4
```

The tooth-space profile is six entities: root arc, left spline, closing line, closing arc,
closing line, right spline. Closing radius is `ra + max(0.5, mn)` for external gears and
`ra − max(0.5, mn)` for internal ones. **The tip land comes from the blank**, so no tip arc is
drawn.

> The original implementation drew `z × 4` entities (80 for a 20-tooth gear) in one sketch and
> extruded. When that fails you get a bare `null` with nothing to go on. Six entities make each
> step independently checkable. This is also what Fusion 360's official SpurGear script, Onshape,
> FreeCAD's FCGear and study-gears all do.

### 3.2 API rules learned the hard way

| Trap | Correct approach |
|---|---|
| `FeatureExtrusion2` is obsolete; `IPartDoc` also has a same-named 16-arg method returning `void` | Use `IFeatureManager.FeatureExtrusion3` (23 args) |
| The profile sketch **must** be selected with **mark 0**; `InsertSketch(true)` does not guarantee it stays selected | `FeatureByPositionReverse(0)` → `Select2(false, 0)`, and check the return value |
| **`AddToDB` must be `true`** | SOLIDWORKS snaps endpoints within roughly **1 mm** by default. The root arc is ~0.1 mm long, so `false` collapses the whole tooth |
| `CreateSpline` ignores `AddToDB` | Documented as "always adds directly to the database" — splines are always exact; arcs are the variable |
| `CreateArc` radius comes from **centre + start point**; the end point only sets the sweep | Compute each seam point once and reuse the same `double`; never derive it twice by different formulas |
| Plane and feature names are localised | Walk features for `GetTypeName2() == "RefPlane"`; index 0/1/2 are front/top/right |
| No way to tell whether a sketch closed | `ISketch.GetSketchContourCount()` — the tooth space must report **1** |
| `CreateArc`'s direction argument is `short` | Cast explicitly: `(short)1` / `(short)-1` |

### 3.3 PropertyManagerPage lifecycle — three hard rules

1. **Snapshot parameters while the page is alive.**
   Measured behaviour: controls are still valid during `OnClose`, but by `AfterClose` they have
   been reset to the values written at creation time. Reading `nb.Value` in `AfterClose` throws
   nothing and the reference is not null — you simply get the initial value back. This is exactly
   why "changing parameters had no effect".
   → Snapshot in `OnClose`; build only from the snapshot. Cross-check against the `val` delivered
   by `OnNumberboxChanged(id, val)`, which comes straight from SOLIDWORKS and is the most
   trustworthy source.

2. **Create a fresh PropertyManagerPage every time you show it.**
   Calling `Show2()` on a page object SOLIDWORKS has already released is an access violation —
   SOLIDWORKS disappears without a dialog.

3. **Wrap every handler callback in try/catch.**
   A managed exception crossing the COM boundary into native code takes the process down.

**Control display gotchas**

- `IPropertyManagerPageNumberbox` and `Combobox` have **no `Caption` property** (verified by
  reflection). The caption argument to `AddControl2` is silently discarded — parameter names must
  be drawn with separate `swControlType_Label` controls.
- A **Label's layout rectangle is fixed at page-build time from its text**; `Height`, `Left` and
  `Width` can only be set before the page is shown. A label created with `""` or `" "` is a
  zero-width row and no later `Caption` assignment will ever appear.
  → Rows that must refresh at runtime use a **read-only Textbox**: an edit control's rectangle
  depends on the control type, not the content, so assigning `Text` always repaints.
- Checkboxes *do* have a caption and display it normally.

### 3.4 COM registration

- The add-in class must be `[ClassInterface(ClassInterfaceType.AutoDispatch)]`.
  With `ClassInterfaceType.None`, `SetAddinCallbackInfo2` throws `InvalidCastException` —
  SOLIDWORKS dispatches toolbar callbacks (`ShowPage` / `EnablePage`) **by name through
  IDispatch**, which requires a dispatch class interface.
- The three interop assemblies must sit next to the add-in DLL; they are not in the GAC, and
  without them even `regasm` fails to load the assembly.
- `[ComRegisterFunction]` writes `HKLM\SOFTWARE\SolidWorks\Addins\{GUID}` (default value `1` =
  load at startup, plus `Title` and `Description`) and `HKCU\Software\SolidWorks\AddInsStartup\{GUID}`.

## 5. Code layout

| File | Responsibility |
|---|---|
| `src/GearMath.cs` | **Pure geometry, no SOLIDWORKS dependency** — reusable on its own |
| `src/GearBuilder.cs` | Blank, tooth space, pattern, bore — the SOLIDWORKS modelling |
| `src/GearPage.cs` | PropertyManagerPage, implements `IPropertyManagerPage2Handler9` (37 members) |
| `src/GearAddin.cs` | `ISwAddin`, CommandManager, COM registration, icon generation, logging |

**The compiler is the .NET Framework `csc.exe`, which supports C# 5 only** — no string
interpolation (`$""`), no `?.`, no `nameof`, no expression-bodied members, no auto-property
initialisers.

After rebuilding you do **not** need to re-register; just restart SOLIDWORKS. The DLL is locked
while SOLIDWORKS runs, so it must be fully closed before the file can be replaced.

### Diagnostics

`GearAddin.Log(string)` writes to `%LOCALAPPDATA%\GearWorks\addin.log`: add-in load sequence,
control creation results, every parameter change, the `OnClose` / `AfterClose` three-way
comparison, and the outcome of each modelling feature.

**Read the log before theorising.** Three separate bugs in this project were misdiagnosed by
reasoning about the API, and each was located immediately once a single line of logging was added.

## 6. Limitations

1. Helical gears produce the transverse profile as a spur solid; add a Flex/twist feature for a
   true helix (the panel reports the angle, `b·tanβ/r`).
2. Internal root fillets are a tangent-arc approximation; the internal path is verified offline
   but has not been exercised in SOLIDWORKS.
3. No interference checking, strength calculation, accuracy grades or tolerance bands; no
   double-helical, bevel or worm gears.
4. Profile shift is user-supplied, not optimised.

### Possible next steps

- Replace the involute/trochoid intersection with BOSL2's approach: build two radius → polar-angle
  lookup tables and take `min(involute, trochoid)`. One line replaces every undercut branch.
- Auto profile shift: `z_min = 2/sin²αt`, `x = (1 − z/z_min)/cosβ`.
- Reduce flank spline points to 12–20 (Fusion uses 10, FreeCAD 20) — too many points make the
  curvature comb ripple.
- English UI strings.
